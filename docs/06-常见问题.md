## 选型与采购

### Q: 自建 VPS 和机场有什么区别？

| | 机场 | 自建 VPS |
|---|---|---|
| 你拥有什么 | 一个订阅链接 | **一整台服务器** |
| IP | 几百人共享 | **你独享** |
| 能做什么 | 只能按它规则代理 | 随便：代理、API 网关、建站、爬虫 |
| 别人能影响你 | 能（共享 IP 被拉黑你遭殃） | 不能 |
| 出问题 | 只能等客服 | 自己能查日志、改配置 |

### Q: 自建就不会被封号了吗？

**不是。** 自建 VPS 仍是**机房 IP（Datacenter）**，不是住宅 IP。

自建的真正价值是 **独享 + 固定 + 少切换** —— 这三点的组合能显著降低风控概率，但不等于免疫。

真正影响账号安全的是**使用习惯**：
- 固定一个节点，不要频繁切国家/ASN
- 不共用账号
- 网页/终端/API 走同一出口

### Q: 需要买域名和 SSL 证书吗？

**不需要。**

- Reality 借用真实大站的 TLS 特征
- Hysteria2 用自签证书（它自带加密层）

这是本方案相对传统 Trojan/VMess+WS+TLS 的最大便利。

### Q: 需要备案吗？

不需要。VPS 在海外。

### Q: 预算多少够？

| 预算 | 能买到 |
|------|--------|
| ¥13–22/月 | RackNerd 等，线路不优化 |
| **¥23–43/月** | **VMISS / ZgoCloud 入门，三网优化** |
| ¥30–50/月 | 搬瓦工常规款（含免费换机房） |
| ¥70+/月 | DMIT Premium（最好，每 15 天免费换 IP） |

### Q: 为什么推荐洛杉矶而不是香港/日本？

**如果要"美国原生 IP"，洛杉矶是唯一选择** —— 它是离中国最近的美国机房（150–220ms）。

香港/日本延迟更低（30–90 ms），但部分 IP 段在境外服务风控体系中评价较差。

这是"延迟"和"风控友好度"的取舍。

## 部署

### Q: 支持哪些系统？

Ubuntu 22.04 / 24.04 已验证。Debian 理论可用但未测试。

### Q: 部署脚本安全吗？会不会偷我数据？

脚本是**明文 bash**，你可以逐行审阅。它做的事情全部列在 [02-部署指南](02-部署指南.md#23-脚本做什么) 里。

**它不做的事**：不装常驻进程、不上报数据、不改系统关键配置、不碰你的其他服务。

### Q: 为什么 `sing-box check` 通过但启动失败？

因为 **`check` 不覆盖所有运行时校验**。

实际遇到的例子：sing-box 1.14 移除了旧版 DNS server 格式，`check` 返回 0，但**启动时 FATAL**。

**所以必须验证 `systemctl is-active sing-box`**，不能只依赖 `check`。

详见 [故障 2](04-故障排查手册.md#2-dns-server-格式在-114-被移除)。

### Q: 部署失败了怎么办？

1. 脚本会打印 `journalctl -u sing-box` 的最近日志
2. 对照 [04-故障排查手册](04-故障排查手册.md) 找对应症状
3. **不要在没排查的情况下重装** —— 可能覆盖有用信息

### Q: 两个协议都要开吗？

建议都开。客户端用 `fallback` 策略组：

- **Hysteria2** 优先（速度最好）
- 不通时自动切 **Reality**（隐蔽性最好）

实际场景：家宽用 HY2，移动网络/敏感时期 Reality 更稳。

## 客户端

### Q: Clash Verge 还是 sing-box 客户端？

| | Clash Verge Rev | sing-box |
|---|---|---|
| 界面 | ✅ 图形化 | 命令行 |
| TUN 权限 | 装一次服务即可 | 每次需管理员 |
| 延迟可视化 | ✅ | ❌ |
| 开机自启 | ✅ 图形配置 | 手动 |
| 推荐度 | **推荐** | 进阶/服务器用 |

### Q: TUN 模式和系统代理要同时开吗？

**建议同时开，但 TUN 是主力。**

- **TUN 模式**：网络层接管，覆盖所有应用（包括不读系统代理的）
- **系统代理**：给读系统代理的应用用（如浏览器）

两者不冲突。TUN 是更可靠的兜底。

### Q: 为什么改了配置不生效？

**Clash Verge 的应用级设置优先级高于 profile 配置。**

```
应用级设置 (verge.yaml)      ← 最高
运行时配置 (clash-verge.yaml) ← 实际喂给内核的
Profile 源配置 (profiles/*)   ← 最低，会被覆盖
```

**排查时永远看 `clash-verge.yaml`**（运行时），那才是内核真正读到的。

详见 [故障 7](04-故障排查手册.md#7-clash-端口设置被覆盖)。

### Q: `claude` / `codex` 连不上，但浏览器正常？

Node 程序**不读 Windows 系统代理**，也不读 `HTTPS_PROXY`（除非开启特定开关）。

```powershell
# 必须设置这个（Node 24+）
[Environment]::SetEnvironmentVariable('NODE_USE_ENV_PROXY','1','User')
```

详见 [故障 11](04-故障排查手册.md#11-node-不读代理环境变量)。

### Q: Codex 桌面端显示"正在重新连接 1/5"？

Codex 的 Rust 后端默认不读系统代理。需要三管齐下：

1. `config.toml` 加 `respect_system_proxy = true`
2. 创建 `~/.codex/.env` 写代理变量
3. 开 TUN 模式

详见 [故障 10](04-故障排查手册.md#10-桌面客户端间歇断连)。

### Q: `chatgpt.com` 返回 403，是 IP 被封了吗？

**大概率不是。** 先确认：

```bash
# 加客户端请求头再试
curl -x http://127.0.0.1:7890 https://chatgpt.com/backend-api/me \
  -H "originator: codex_cli_rs" -H "User-Agent: codex_cli_rs/0.154.0"
```

如果变成 401（而不是 403 challenge），说明 **IP 没问题，只是缺认证头**。

详见 [故障 12](04-故障排查手册.md#12-cloudflare-403-的真相)。

### Q: WSL 连不上代理？

三个常见原因：

1. 混合入站绑的是 `127.0.0.1` 而非 `0.0.0.0`（WSL 过不来）
2. WSL 里没设 `HTTP_PROXY` 环境变量
3. **Windows 防火墙有自动生成的 Block 规则**

详见 [故障 5](04-故障排查手册.md#5-wsl-连不上-windows-代理)。

## 性能

### Q: 延迟多少算正常？

| 线路 | 正常范围 |
|------|---------|
| 美西优化线路（9929/CMIN2/CUII） | **150–220 ms** |
| 美西国际线路 | 200–300 ms，波动大 |
| 香港 | 30–50 ms |
| 东京 | 50–90 ms |

**晚高峰（19:00–23:00）复测**，如果比白天差很多，说明线路没优化。

### Q: 代理突然变得极慢（好几秒）？

**90% 是 DNS 配置问题。**

检查 Clash 的 `dns.nameserver` 是否写了 `1.1.1.1` / `8.8.8.8` —— 这两个在国内**直连不稳定**，每次解析要等超时。

改用国内 DNS：

```yaml
dns:
  enhanced-mode: fake-ip
  respect-rules: true
  nameserver:
    - https://223.5.5.5/dns-query
    - https://119.29.29.29/dns-query
```

详见 [故障 8](04-故障排查手册.md#8-延迟-4878ms-到-197ms)。**实测从 4878ms 降到 197ms。**

### Q: 国内网站也变慢了？

**检查代理模式是否被设成了"全局"。**

```
规则模式: 国内直连           → 百度 236ms
全局模式: 国内也绕道美国     → 百度 1674ms
```

详见 [故障 13](04-故障排查手册.md#13-全局模式导致流量浪费)。

### Q: 流量消耗很快？

先算一下推算日消耗：

```
推算日消耗 = 累计流量 / 已运行小时 × 24
```

如果 **>50 GB/天**，几乎肯定是全局模式。

其次检查是否有大流量应用走了代理（视频、下载、云盘同步）。可以用规则把它们分流到直连。

### Q: 为什么会有上传流量？

VPS 的 **TX（发送）** 就是你把网页/API 响应下载回来的数据。所以上下行大致相当是正常的。

## 安全与风控

### Q: 我需要住宅 IP 吗？

**大多数情况不需要。**

对 AI 工具而言，**"长期固定、来源清楚、少切换"比"住宅"标签更重要**。

住宅 IP 是高预算升级项（通常 ¥34/月起且带宽小），不是入门必需。

### Q: 共享住宅代理池能用吗？

**不建议用于 AI 账号登录。**

它的核心能力是"换 IP"，而 AI 工具需要的是"不乱换"。频繁变化的国家/城市/IP 会让环境更不稳定。

它适合数据采集、价格监控，不适合长期账号。

### Q: 一个 VPS 能给几台设备用？

| 规模 | 配置要求 |
|------|---------|
| 1–10 台设备 | 1核 1GB 够 |
| 10–20 台 | 2核 2GB |
| 20+ 台 | 建议每人自建 |

**注意流量**：10 台设备日常使用月均 300GB 左右。

### Q: 会被 VPS 商家看到流量吗？

VPS 提供商能看到**流量元数据**（连接目标、时间、大小），但看不到**内容**（TLS 加密）。

Reality/Hysteria2 的加密层保证内容安全。

### Q: 配置文件里的密钥要怎么保护？

| 文件 | 敏感内容 | 处理 |
|------|---------|------|
| `params.txt` | Reality 私钥 | 不进 git，不分享 |
| `clash-verge.yaml` | HY2 密码、UUID | 同上 |
| `~/.claude/settings.json` | API Token | 定期轮换 |
| `~/.codex/auth.json` | OAuth Token | 不要外传 |

**如果任何凭据曾出现在聊天记录、截图、公开仓库中，立即轮换。**

## 维护

### Q: 需要多久维护一次？

**几乎零维护。** 脚本已配置每 20 天自动更新。

建议每月做一次：

```bash
# 1. 服务是否正常
systemctl is-active sing-box

# 2. 流量是否超
# 看商家面板

# 3. 出口 IP 是否正常
curl -s https://ipinfo.io/json
```

### Q: IP 被墙了怎么办？

**症状**：ping 不通、SSH 超时、客户端全断。

| 商家 | 换 IP 方式 | 费用 |
|------|-----------|------|
| 搬瓦工 | **换机房**（等效换 IP） | **免费** |
| DMIT | 后台一键换 IP | 每 15 天免费一次 |
| 其他 | 提工单 / 付费换 IP | 视商家 |

**预防**：不要在 VPS 上搭公开网站、不要用默认 22 端口 SSH、开 fail2ban。

### Q: 自动更新会弄坏配置吗？

脚本的更新任务是：

```bash
apt update && apt upgrade -y && curl -fsSL https://sing-box.app/install.sh | sh && systemctl restart sing-box
```

**风险点**：sing-box 大版本升级可能引入配置格式变更（如 1.14 移除旧 DNS 格式）。

**建议**：更新后立刻验证：

```bash
systemctl is-active sing-box
journalctl -u sing-box -n 30
```

如果挂了，可以降级：

```bash
curl -fsSL https://sing-box.app/install.sh | sh -s -- --version 1.13.0
```

### Q: 磁盘满了怎么办？

常见原因：

1. **日志累积** —— `journalctl --vacuum-size=100M`
2. **应用数据目录膨胀** —— 检查各程序的数据目录
3. **apt 缓存** —— `apt clean`

### Q: 怎么监控服务是否在线？

最简单的方案：写个定时任务，检测失败时发通知。

```bash
# VPS 上：检测代理端口是否可连
*/5 * * * * curl -s -o /dev/null -m 10 -x http://127.0.0.1:7890 https://www.gstatic.com/generate_204 || echo "代理异常 $(date)" >> /var/log/proxy-health.log
```

更完善的方案可以接微信/Telegram 通知。
